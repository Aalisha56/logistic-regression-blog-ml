01 / THE IDEA

What problem does it solve?

Logistic Regression is a supervised classification method that estimates the probability of a class. Despite its name, it is commonly used for classification rather than numeric prediction. It is a strong baseline when we need interpretable probabilities—for example, estimating whether a customer will renew, whether a transaction may be fraudulent, or whether a sample belongs to one of two categories.

A straight line can produce values below zero or above one, which cannot be probabilities. Logistic Regression maps a weighted combination of features through the sigmoid function, keeping the predicted probability between zero and one.

p(y=1|x) = 1 / (1 + e⁻ᶻ), where z = β₀ + β₁x₁ + … + βₚxₚ

02 / METHOD

How it works, step by step

  1. 01
    Encode the target as the class of interest and the alternative class.
  2. 02
    Prepare numeric features and encode categorical features where needed.
  3. 03
    Estimate weights that make observed labels likely under the predicted probabilities.
  4. 04
    Convert each probability to a class using a chosen decision threshold.
  5. 05
    Evaluate both ranking and classification errors; select a threshold appropriate to the real costs.

03 / VOCABULARY

Concepts worth knowing

Probability

A score between 0 and 1 expressing the model’s estimated chance of the positive class.

Sigmoid

σ(z)=1/(1+e⁻ᶻ), a smooth curve that maps any real score to a probability.

Threshold

A decision rule such as 0.50; it can be changed when false positives and false negatives have different costs.

Precision

Of predicted positives, the share that truly are positive.

Recall

Of actual positives, the share successfully identified.

Regularisation

A penalty that discourages overly large coefficients and can improve generalisation.

04 / IN PRACTICE

A realistic use case

For a subscription service, a model could estimate the probability that an account will cancel. A retention team might choose a lower threshold to catch more at-risk accounts, accepting more false alarms. A medical screening workflow may also prioritise recall, but thresholds must be chosen with domain experts and validated data.

Questions to ask before trusting the result

  • Does the data represent the population or workflow where the model will be used?
  • Are important features missing, noisy, or measured after the outcome?
  • Would a wrong prediction have unequal costs for different groups?
  • Can the result be checked on data not used to build or tune the method?

07 / INTERPRETATION

How to interpret the output

A probability curve shows how the estimated chance changes with a feature when other factors are held fixed in the illustration. The confusion matrix reveals the kinds of mistakes at a selected threshold. ROC curves compare true-positive and false-positive rates across thresholds; they do not choose the business threshold for you.

Do not confuse a pattern with proof

A plot is evidence about the rows and variables it displays. It does not by itself establish causation, guarantee performance on future data, or show that a model will remain reliable after the data distribution changes. Document assumptions and evaluate the method in the context where it will be used.

08 / TRADE-OFFS

Strengths and limitations

Where it helps

  • Produces interpretable class probabilities
  • Fast and a useful baseline
  • Can be regularised for many features
  • Supports binary and multiclass extensions

Where to be careful

  • May underfit complex nonlinear boundaries
  • Needs sensible feature preparation
  • Probability quality can suffer under class imbalance or distribution shift
  • A threshold of 0.5 is not universally best

When should you use it?

Use it when calibrated or interpretable probabilities matter and the decision boundary is reasonably simple. Compare precision, recall, calibration, and the cost of errors—not accuracy alone.

10 / TAKEAWAY

What to remember

Use it when calibrated or interpretable probabilities matter and the decision boundary is reasonably simple. Compare precision, recall, calibration, and the cost of errors—not accuracy alone.

The best workflow is not simply to run an algorithm and show a graph. It is to define the question, prepare the data, explain the method, examine evidence, test limitations, and communicate what can reasonably be concluded.

11 / WORKED EXAMPLE

Worked example: probability is not certainty

Suppose a model returns a churn probability of 0.68 for one account. With a 0.50 threshold, the account is flagged as likely to churn; with a 0.70 threshold, it is not. Neither threshold is automatically correct. The choice depends on intervention cost, the cost of missing a customer who will leave, and the number of accounts a team can contact.

  • Review precision and recall at candidate thresholds.
  • Check probability calibration if probabilities will guide decisions.
  • Do not use the example threshold as a universal business rule.

12 / REPRODUCIBLE WORKFLOW

Implementation blueprint

This optional Python example shows the usual workflow for the included CSV. It is source code for running locally, not code that runs inside this static article. Install the listed libraries first, keep the dataset file beside the script, and use the printed output as a starting point for interpretation—not as a substitute for checking assumptions.

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

df = pd.read_csv("customer_churn_teaching_data.csv")
X = df[["usage_hours", "support_tickets", "tenure_months"]]
y = df["churn"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=7, stratify=y
)
model = make_pipeline(StandardScaler(), LogisticRegression())
model.fit(X_train, y_train)
print(classification_report(y_test, model.predict(X_test)))

How to read it: the code selects the relevant columns, applies the algorithm, and prints a summary or evaluation. Results can vary with random sampling and package versions. For a real project, document the split, parameters, metrics, and any preprocessing choices.

13 / QUALITY CHECK

Common mistakes to avoid

  • Reporting accuracy alone on an imbalanced dataset.
  • Choosing a threshold without considering error costs.
  • Scaling or selecting features using the full dataset before splitting.

Before publishing a conclusion, ask whether the data supports the statement, whether the chart matches the stated method, and whether a reader could reproduce the workflow from the included files.
